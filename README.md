# PlanMyTravel

PlanMyTravel is a server-rendered travel planning and trip management app built
with Flask, Jinja, vanilla HTML/CSS/JavaScript, Turso/libSQL, and Gemini.

## Setup

1. Create and activate a virtual environment, then install dependencies:

   ```sh
   python -m venv .venv
   . .venv/bin/activate
   pip install -r requirements.txt
   ```

2. Copy `.env.example` to `.env`. Keep all credentials server-side. Configure
   `FLASK_SECRET_KEY`, your Turso URL and auth token, and one or more Gemini API
   keys. For travel inventory, configure the Hotelbeds API key and secret as
   `HOTELBEDS_API_KEY` and `HOTELBEDS_API_SECRET`, and a SerpApi key as
   `SERPAPI_API_KEY`. Hotelbeds defaults to its test environment; switch
   `HOTELBEDS_BASE_URL` to `https://api.hotelbeds.com` only after production
   access is enabled. Test results are not live bookable inventory. Keep all
   credentials server-side. The app also recognizes the existing labels `TURSO AUTH URL`,
   `TURSO AUTH TOKEN`, `GEMINI API KEY 1`, and `GEMINI API KEY 2` in `.env`.
   Do not commit `.env`. Set `FLASK_ENV=production` in production; session
   cookies use HTTPS-only mode by default there. Set `SESSION_COOKIE_SECURE`
   explicitly only when your deployment requires overriding that behavior.
   Configure `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and
   `CLOUDINARY_API_SECRET` for image storage. Admin and profile image uploads
   are sent directly to Cloudinary and are not written to local media folders.

3. Initialize the schema and upload the site images:

   ```sh
   python scripts/init_db.py
   python scripts/sync_images.py
   ```

   To migrate existing files under `images/` and `uploads/` to Cloudinary,
   run `python -m scripts.migrate_media_to_cloudinary --apply`. The migration
   updates the media library to serve the Cloudinary URLs and keeps the local
   originals as a rollback copy.

   When Turso URL and auth token are absent, the app uses a local SQLite database
   under `instance/` for offline development.

4. (Optional) Set `ADMIN_BOOTSTRAP_EMAIL` and `ADMIN_BOOTSTRAP_PASSWORD`, then
   run:

   ```sh
   python -m scripts.create_admin
   ```

   Clear the bootstrap password from `.env` after first login.

5. Start the development server:

   ```sh
   flask --app run.py run --debug --host 0.0.0.0
   ```

   In Codespaces, open or forward port `5000` to access the site in your
   browser. The development server should not be exposed to the public internet.

## Creating a Turso database

The application connects to an existing Turso/libSQL database. One-time setup
can be done with the Turso CLI:

```sh
turso db create planmytravel
turso db show planmytravel --url
turso db tokens create planmytravel
```

Or use `scripts/create_turso_db.py` with `TURSO_API_TOKEN` and `TURSO_ORG`.
Copy its reported database URL and token into `.env`, then run the schema
initializer.

## Architecture

`app/` contains the Flask app factory, request handlers, business services, and
hand-written parameterized SQL. Pages are rendered by Jinja; small vanilla
JavaScript modules enhance live catalog search, image galleries, itinerary
editing, media selection, and admin interactions. `/images/` is served from the
configured image directory. Admin uploads are validated and optimized into the
repository's `uploads/` directory and served from `/uploads/`; catalog and media
records store relative paths rather than machine-specific absolute paths.
Media uploads and migrated catalog images are stored in Cloudinary; existing
local originals are retained for recovery, and local image routes redirect to
the corresponding Cloudinary asset after migration.

Destination search covers published destinations, packages, active guides, and
published experiences, with category, travel style, estimated budget, rating,
sorting, and pagination filters. Destination and package detail pages load
gallery entries from the media database and provide thumbnails, navigation,
lightbox viewing, lazy loading, swipe support, counters, and a fallback image.
Favorites require a signed-in traveler.

The admin workspace at `/admin` manages destinations, packages, experiences,
guides, media uploads, review moderation, bookings, travelers, featured
homepage content, site details, admin accounts, and an audit log. Create an
initial super-admin with `ADMIN_BOOTSTRAP_EMAIL` and
`ADMIN_BOOTSTRAP_PASSWORD`, then run `python -m scripts.create_admin` as
described above. Super-admins can create and deactivate admin accounts from
the Admin users page; account IDs are generated by the `admin_users` table and
passwords are stored as hashes in Turso, never as plaintext.

The AI trip planner searches SerpApi Google Flights for round-trip flights
using three-letter IATA airport codes, and Hotelbeds for hotel availability
using the selected destination. Results are included alongside the generated
itinerary. Hotelbeds test credentials and production credentials use different
base URLs; production access must be enabled by Hotelbeds. Search results are
not reservations, and prices and availability must be rechecked with the
provider before booking.

Traveler accounts use signed, HTTP-only Flask sessions with CSRF protection.
Selecting “Remember me” keeps a login across browser sessions until the
configured session lifetime expires. Password changes and account deactivation
invalidate older sessions. Profile and travel preferences are available from
the account settings pages.
